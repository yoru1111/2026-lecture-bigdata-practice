# Task 2 · Crossover 측정 결과

## 측정 방법 및 컴퓨터 (A6)

사용자가 제공한 실제 측정 JSON을 분석했다. n=250,500,1000은 두 번 측정되어 있으며 대표 표에는 두 번째 측정값을 사용한다. 모든 원본 측정은 보존해야 한다. 서로 다른 크기 5개, 범위 4000/250=16배로 A1을 충족한다.

- CPU: AMD Ryzen 5 7430U with Radeon Graphics (앞서 사용자가 제공한 사양 화면 기준)
- RAM: 설치 16GB (앞서 사양 화면 기준)
- OS: Windows-11-10.0.26200-SP0
- Python: 3.14.6
- 측정 중 실행한 다른 프로그램: 미기록, 사용자 확인 필요

JSON 자체에는 RAM이 null이고 CPU가 일반적인 식별 문자열로 기록되어 있다. 위 모델과 설치 RAM은 별도로 확인한 사양이며 원본 JSON을 임의 수정하지 않았다.

데이터는 Task 2 전용 exact-n 생성기, seed=246, threshold=0.6이다. 크기별 데이터는 같은 seed로 재현할 수 있지만 서로 완전히 중첩되는 데이터는 아니다. bench.py는 수정하지 않았다.

## 실행 시간과 비교 횟수 (A3)

| n | BruteForce (초) | LSH (초) | BruteForce 비교 | LSH 비교 |
|---:|---:|---:|---:|---:|
| 250 | 0.4135 | 8.2306 | 31,125 | 15 |
| 500 | 1.5751 | 9.0024 | 124,750 | 29 |
| 1,000 | 5.7475 | 9.9768 | 499,500 | 57 |
| 2,000 | 24.0182 | 11.9997 | 1,999,000 | 115 |
| 4,000 | 103.5526 | 16.0954 | 7,998,000 | 238 |

## 제곱 증가 확인 (A4)

| 크기 증가 | T(2n)/T(n) |
|---|---:|
| 250 → 500 | 3.809 |
| 500 → 1,000 | 3.649 |
| 1,000 → 2,000 | 4.179 |
| 2,000 → 4,000 | 4.311 |

두 배 크기에서 시간은 약 3.65~4.31배로 증가했다. 정확히 4배는 아니지만 대체로 제곱 증가와 일치한다. 비교 횟수는 모든 크기에서 n(n-1)/2와 정확히 일치한다. 단일 측정 및 시스템 부하 등의 영향이 있을 수 있으며, 차이를 전부 특정 원인으로 단정하지 않는다.

첫 번째 측정에서는 250→500의 비율이 약 3.888, 500→1000이 약 3.849였다. 두 번째 측정의 LSH 시간은 첫 번째보다 낮았지만 원인이 기록되어 있지 않아 원인을 확정할 수 없다.

## 최대 크기의 메모리 (A5)

n=4000에서:

| 방법 | 최대 추적 메모리 (바이트) | MiB |
|---|---:|---:|
| BruteForce | 29,416 | 0.0281 |
| LSH | 10,142,880 | 9.6730 |

tracemalloc이 추적한 Python 할당의 peak다. 입력 문서는 추적 시작 전에 생성되므로 입력 문서 메모리를 포함하지 않는다. 전체 프로세스 RAM, 컴퓨터 전체 사용량 또는 메모리 부족 여부로 해석하면 안 된다. 메모리 추적의 실행 시간 오버헤드도 포함된 측정이므로 교차점은 이 측정 방식에 대한 결과다.

## 교차점과 준비 비용 (A7–A8)

n=1000에서는 BruteForce 5.7475초가 LSH 9.9768초보다 빠르다. n=2000에서는 LSH 11.9997초가 BruteForce 24.0182초보다 빠르다. 따라서 측정된 첫 역전 크기는 n=2000이고, 교차 구간은 1000과 2000 사이로 관찰된다. 정확한 교차 n은 추가 측정 없이는 알 수 없다.

LSH는 서명 생성 전에 shingle별 문서 postings를 만들고, 각 고유 shingle에 160개 해시를 적용하며 문서별 최솟값을 갱신한다. 이어서 40개 밴드 키와 버킷을 만들고 후보를 중복 제거한다. 작은 n에서는 이 준비 비용이 모든 쌍을 비교하는 비용보다 크다. 어휘 수가 5000으로 고정되어 고유 shingle의 수가 포화될 수 있으므로 LSH 시간 증가를 단순한 문서 수 비례로 단정해서는 안 된다.

n=4000에서 비교 감소율은 약 99.9970%이며, 시간은 LSH가 약 6.43배 빠르다. 두 방법이 반환한 쌍의 수는 각 크기에서 동일했지만, 이번 JSON은 쌍 자체를 담지 않아 집합의 완전 일치나 recall을 그 사실만으로 입증하지는 않는다.

## 불편해진 크기 (A2)

n=4000에서 BruteForce가 103.55초(약 1분 44초) 걸렸다. 과제에서 제시한 ‘1분 기다림’의 객관적인 시간 기준을 넘었다. LSH는 16.10초였다. 이 측정에서 확인된 부담은 시간이며 메모리 부족을 보여주는 증거는 없다. 실제 체감 불편과 메모리 압박 여부는 사용자 확인이 필요하다.
